1. EXECUTIVE SUMMARY & LIFECYCLE OVERVIEW
====================================================================================================
The Material Request system is the core supply-chain backbone of the application. It manages the
full lifecycle of construction material requisition—from initial identification of site requirements
by a Site Supervisor, through technical verification by the Project Manager, corporate financial/HQ
budget authorization by the Organization Executive, dispatch and stock release from central
warehouses, down to final physical material intake and consumption at the construction site.

Key Highlights:
- Multi-Tier Hierarchy: Supervisor (Site) -> Manager (Regional/Technical) -> Organization (HQ/Finance)
- Strict Audit Trail: Every status change logs actor name, role, timestamp, action, and comments.
- Dual-Ledger Inventory: Live synchronization between central company stock (`companyAvailableCount`)
  and site-level inventory ledger (`siteInventories`).
- Push & In-App Notifications: Automatic alerts delivered to relevant actors on state transitions.

3. USER ROLES & RESPONSIBILITIES
====================================================================================================

1. SITE SUPERVISOR (Field Operations)
   - Views sites assigned via `siteSupervisorMap`.
   - Creates new requisitions using `MaterialRequestForm`.
   - Tracks live status and audit timeline using `SupervisorMaterialViewRequestScreen`.
   - Inspects received deliveries and updates site balance via `MaterialAtSiteEntryPage`.

2. PROJECT MANAGER (Technical & Logistics Coordinator)
   - Oversees multiple sites and all pending material requests in `ManagerMaterialApprovalScreen`
     and `ManagerApprovalsCenterPage`.
   - Verifies legitimacy of material requests and adjusts quantities if necessary.
   - Forwards verified requests to Org HQ or rejects duplicate/unwarranted requests.
   - Executes warehouse release, stock deduction, and dispatch upon HQ authorization.

3. ORGANIZATION ADMIN / HQ OWNER (Executive / Financial Governance)
   - Exercises overall budget and compliance governance in `OrganizationDashboard`.
   - Approves procurement spending and vendor releases.
   - Has full visibility across all project portfolios and company-wide inventory metrics.

4. 5-STAGE LIFECYCLE & STATE MACHINE SPECIFICATION
====================================================================================================

The workflow is governed by `ApprovalWorkflowService` using explicit status strings and enum states:

----------------------------------------------------------------------------------------------------
Status String                  | Enum Stage               | Active Step | Actionable By
----------------------------------------------------------------------------------------------------
'pending_manager_review'       | pendingManagerReview     | 1           | Manager
'pending_org_approval'         | pendingOrgApproval       | 2           | Organization Admin
'pending_manager_clearance'    | pendingManagerClearance  | 3           | Manager
'approved'                     | approved                 | 4           | Supervisor (Receipt)
'rejected_by_manager'          | rejectedByManager        | -1 (Closed) | None
'rejected_by_org'              | rejectedByOrg            | -1 (Closed) | None
----------------------------------------------------------------------------------------------------

Detailed Transition Rules:
1. `submitRequest`:
   - Input: Site ID, Project Name, Material List, Supervisor Details.
   - Set status = 'pending_manager_review', currentStep = 1.
   - Appends initial audit log entry to `approvalHistory`.
   - Sends Notification to all Managers.

2. `managerVerifyAndForward`:
   - Input: Document ID, Manager Name, Review Remarks.
   - Set status = 'pending_org_approval', currentStep = 2.
   - Appends Manager verification audit log to `approvalHistory`.
   - Sends Notification to Organization HQ.

3. `orgApprove`:
   - Input: Document ID, Org User Name, Authorization Remarks.
   - Set status = 'pending_manager_clearance', currentStep = 3.
   - Appends Org approval audit log to `approvalHistory`.
   - Sends Notification to Manager for warehouse dispatch.

4. `managerFinalClearance`:
   - Input: Document ID, Manager Name, Dispatch Remarks.
   - Set status = 'approved', currentStep = 4.
   - Appends final release audit log to `approvalHistory`.
   - Sets `completedAt` timestamp.
   - Triggers stock transfer in `materialsAvailability` / `materialTransfer`.
   - Sends Notification to Supervisor that material is released and awaiting arrival confirmation.

5. `supervisorConfirmArrival` (Post-Release Verification):
   - Input: Document ID, Supervisor Name & ID, Proof Image URL, Remarks.
   - Sets `arrivalConfirmationStatus` = 'confirmed', `arrivalConfirmedAt` = server timestamp.
   - Saves `arrivalProofImageUrl` and optional `arrivalConfirmationRemarks`.
   - Appends Step 5 audit log entry to `approvalHistory`.
   - Sends Notification to Manager confirming physical delivery with photo proof.

6. `managerReject` / `orgReject`:
   - Set status = 'rejected_by_manager' or 'rejected_by_org', currentStep = -1.
   - Appends rejection reason and actor to `approvalHistory`.
   - Sends alert notification back to Supervisor.

5. FIRESTORE DATABASE SCHEMA & DATA DICTIONARY
====================================================================================================

1. COLLECTION: `siteMaterialsRequest` (Primary Requisitions Store)
   Document ID: `${siteId}_${yyyyMMdd}` or custom generated unique ID.
   Fields:
   - `matReqId` (String): e.g., "MR001", "MR002" (Sequential requisition code)
   - `siteId` (String): e.g., "ST001_shek"
   - `projectName` (String): e.g., "Skyline Residency"
   - `projectStage` (String): e.g., "Foundation", "Structure"
   - `supervisorName` (String): Requisitioning supervisor's full name
   - `supervisorId` (String): Auth UID / Supervisor ID
   - `date` (String): Human-readable formatted creation date
   - `materials` (Array of Objects):
     [
       {
         "materialName": "Cement OPC 53 Grade",
         "materialQty": 100,
         "materialUnit": "Bags",
         "priority": "Immediate" | "High" | "Medium" | "Low"
       }
     ]
   - `status` (String): 'pending_manager_review' | 'pending_org_approval' |
                        'pending_manager_clearance' | 'approved' |
                        'rejected_by_manager' | 'rejected_by_org'
   - `statusDisplay` (String): e.g., "Pending Manager Review"
   - `currentStep` (Number): 1, 2, 3, 4, or -1
   - `managerName` (String): Name of manager who verified
   - `managerReviewRemarks` (String): Remarks added during Stage 2
   - `orgApprovedBy` (String): HQ admin who authorized in Stage 3
   - `orgApprovalRemarks` (String): Remarks added during Stage 3
   - `finalApprovedBy` (String): Manager who cleared in Stage 4
   - `finalClearanceRemarks` (String): Final release notes
   - `rejectionReason` (String): Provided if rejected
   - `arrivalConfirmationStatus` (String): 'confirmed' (or null/empty when pending)
   - `arrivalConfirmedBy` (String): Name of supervisor confirming receipt
   - `arrivalConfirmedById` (String): UID of confirming supervisor
   - `arrivalConfirmedAt` (Timestamp): Timestamp of physical arrival confirmation
   - `arrivalProofImageUrl` (String): Download URL of uploaded arrival proof photo
   - `arrivalConfirmationRemarks` (String): Optional delivery notes
   - `approvalHistory` (Array of Objects): Full immutable chronological audit trail
     [
       {
         "step": "1. Supervisor Submission",
         "action": "Request Submitted",
         "actorRole": "Supervisor",
         "actorName": "John Doe",
         "actorId": "SUP101",
         "remarks": "Urgent requirement for slab casting.",
         "timestamp": Timestamp,
         "dateStr": "Sep 04, 2026 • 10:30 AM"
       },
       ...
       {
         "step": "5. Material Arrival Confirmation",
         "action": "Material Arrival Confirmed",
         "actorRole": "Supervisor",
         "actorName": "John Doe",
         "actorId": "SUP101",
         "remarks": "Received 100 bags in good condition. Proof photo uploaded.",
         "timestamp": Timestamp,
         "dateStr": "Sep 04, 2026 • 04:30 PM"
       }
     ]
   - `createdAt` (Timestamp): Server timestamp
   - `updatedAt` (Timestamp): Server timestamp
   - `completedAt` (Timestamp): Server timestamp when fully approved

2. COLLECTION: `materialsAvailability` & `materialTransfer` (Dual-Ledger Inventory)
   Document ID: Sanitized material name, e.g., "cement_opc_53_grade"
   Fields:
   - `materialName` (String): Canonical material name
   - `displayName` (String): Formatted name for UI
   - `category` (String): e.g., "Raw Materials"
   - `unit` (String): e.g., "Bags", "Tons", "Pieces"
   - `unitPrice` (Number): Rate per unit
   - `companyAvailableCount` (Number): Warehouse stock remaining
   - `totalSiteCount` (Number): Sum of all stock across all construction sites
   - `totalAvailableCount` (Number): Total company + site stock
   - `siteInventories` (Array of Objects):
     [
       {
         "siteId": "ST001_shek",
         "siteName": "Skyline Project Site A",
         "projectName": "Skyline Residency",
         "availableCount": 150,
         "updatedAt": "2026-09-04T12:00:00.000Z"
       }
     ]
   - `lastUpdated` (Timestamp): Last stock modification date

3. COLLECTION: `materialMovements` (Dispatches & Transfers Audit)
   Fields:
   - `movementId` (String): Unique transaction key
   - `materialName` (String): Transferred item
   - `fromLocation` (String): "Company Warehouse"
   - `toSiteId` (String): Destination site ID
   - `quantity` (Number): Amount transferred
   - `transferredBy` (String): Manager name
   - `receivedBy` (String): Supervisor name
   - `timestamp` (Timestamp): Execution time
   - `type` (String): "TRANSFER" | "CONSUMPTION" | "RETURN"

4. COLLECTION: `notifications` (Real-Time In-App Alert Queue)
   Fields:
   - `title` (String): Alert header
   - `body` (String): Alert description
   - `recipientRole` (String): "Manager" | "Supervisor" | "Organization"
   - `recipientId` (String): Target user UID or name
   - `requestType` (String): "material"
   - `requestId` (String): Reference requisition ID
   - `docId` (String): Firestore document path
   - `status` (String): Lifecycle state
   - `isRead` (Boolean): Read state indicator
   - `timestamp` (Timestamp): Time fired

6. INVENTORY & STOCK SYNCHRONIZATION MECHANISM
====================================================================================================

The application uses `MaterialInventoryService` to maintain real-time consistency between
central supply and field consumption:

1. Stock Addition (Warehouse Inflow):
   - Manager adds central stock via `Material Availability -> Update` tab.
   - `MaterialInventoryService.setCompanyStock(materialName, count, isAddition: true)` updates
     `companyAvailableCount` in both `materialsAvailability` and `materialTransfer` atomically.

2. Stock Allocation (Company -> Site Dispatch):
   - Triggered upon Stage 4 Final Clearance:
   - `MaterialInventoryService.transferCompanyToSite(...)` executes:
     a) Decrements `companyAvailableCount` by `requestedQty`.
     b) Finds matching site in `siteInventories` list.
     c) Increments site's `availableCount` by `requestedQty`.
     d) Recomputes `totalSiteCount` and `totalAvailableCount`.
     e) Writes simultaneously to `materialsAvailability`, `materialTransfer`, and mirrors.

3. Site Consumption (Field Usage):
   - Supervisor logs daily consumption in site reports.
   - Deducts from site-specific balance in `siteInventories[siteId].availableCount`.

7. REAL-TIME NOTIFICATIONS & AUDIT TRAIL LOGGING
====================================================================================================

1. Audit Trail:
   Every transition in `ApprovalWorkflowService` creates an immutable map:
   `createAuditEntry(step, action, actorRole, actorName, actorId, remarks)`
   This is appended using `FieldValue.arrayUnion([auditEntry])`, ensuring no previous
   action can be overwritten or tampered with.

2. Visual Timeline:
   Both Supervisor and Manager views render `ApprovalLifecycleStepper` widget:
   - Shows horizontal/vertical interactive timeline with color-coded nodes:
     * Green checkmark: Step completed successfully.
     * Blue pulsing circle: Current pending step.
     * Grey dashed circle: Upcoming step.
     * Red cross: Rejected step.
   - Expands to display actor name, exact timestamp, and verification remarks.

3. Notification Triggers:
   - Supervisor submits -> `NotificationService.notifyManager(...)`
   - Manager forwards   -> `NotificationService.notifyOrganisation(...)`
   - Org Authorizes     -> `NotificationService.notifyManager(...)`
   - Manager releases   -> `NotificationService.notifySupervisor(...)`
   - Any rejection      -> `NotificationService.notifySupervisor(...)` & `notifyManager(...)`

9. STEP-BY-STEP USER JOURNEY & INTERACTION FLOW
====================================================================================================

Example Walkthrough: 200 Bags of Cement Requisition

1. Site Supervisor (Morning 09:00 AM):
   - Opens app, goes to Supervisor Dashboard -> "Material Request".
   - Selects Site: "ST001_shek (Skyline Residency)".
   - Selects Material: "Cement OPC 53 Grade".
   - Enters Quantity: "200", Unit: "Bags", Priority: "Immediate".
   - Clicks "Submit Requisition".
   - Firestore creates document in `siteMaterialsRequest` with `status: 'pending_manager_review'`.

2. Project Manager (Morning 10:15 AM):
   - Receives notification: "📋 New Material Request Submitted by John Doe for Site ST001_shek".
   - Opens `ManagerMaterialApprovalScreen` -> "Pending Review" tab.
   - Taps on the card to inspect details and stock history.
   - Enters remarks: "Verified with structural engineer. Foundation stage ready."
   - Clicks "Verify & Forward to HQ".
   - Status updates to `'pending_org_approval'`.

3. Organization Executive (Afternoon 01:30 PM):
   - Receives notification: "🏢 Material Request Forwarded for HQ Approval".
   - Opens `OrganizationDashboard` -> Approvals Center.
   - Reviews requested budget vs. project cashflow.
   - Enters remarks: "Budget authorized against PO #9942."
   - Clicks "Authorize Requisition".
   - Status updates to `'pending_manager_clearance'`.

4. Project Manager (Afternoon 02:45 PM):
   - Receives notification: "✅ Material Request Authorized by HQ".
   - Opens `ManagerMaterialApprovalScreen`.
   - Clicks "Release & Approve".
   - System automatically deducts 200 Bags from Central Warehouse and logs transfer.
   - Status updates to `'approved'`.

5. Site Supervisor (Afternoon 04:00 PM):
   - Receives notification: "🎉 Material Request Approved & Released!".
   - Vehicle arrives at site; Supervisor opens `MaterialAtSiteEntryPage`.
   - Confirms arrival of 200 Bags of Cement into site inventory.
   - Material is immediately available for site work logs.

10. EDGE CASES, ERROR HANDLING & RESILIENCE
====================================================================================================

1. Insufficient Warehouse Stock:
   - When Manager releases goods, if `companyAvailableCount` < `requestedQty`, the system clamps
     the company count to 0 and records available balance without crashing.
   - Manager can adjust approved quantity prior to release.

2. Offline & Network Resiliency:
   - Firestore offline persistence ensures requests created in low-connectivity areas are queued
     and synchronized automatically upon reconnecting.

3. Legacy Field Fallbacks:
   - The system handles variations in field names across older documents (e.g. `matReqId` vs `docId`,
     `companyAvailableCount` vs `count`, `materials` array vs single item schema).
