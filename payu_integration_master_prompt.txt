1. EXECUTIVE PROJECT ARCHITECTURAL ANALYSIS
================================================================================

The PayU integration in this codebase is built as an enterprise-grade, hybrid
architecture designed to maximize payment success rates, security, and developer
productivity.

KEY TECHNICAL PILLARS:

1. CRYPTOGRAPHIC DUAL-HASHING (ZERO FAILURE RISK):
   • Request Hash Formula (SHA-512):
     sha512(key|txnid|amount|productinfo|firstname|email|udf1|udf2|udf3|udf4|udf5||||||salt)
   • Response Hash Verification Formula (SHA-512):
     sha512(salt|status||||||udf5|udf4|udf3|udf2|udf1|email|firstname|productinfo|amount|txnid|key)
   • Backend-First Generation: Hash is generated securely by Cloud Function
     `generatePayUHash`. If backend is unreachable or timeout occurs, client
     seamlessly falls back to local SHA-512 calculation.

2. HYBRID WEBVIEW & JS EXTRACTION BRIDGE:
   • The app loads a base64-encoded HTML document that posts form data directly
     to PayU endpoint (https://test.payu.in/_payment or https://secure.payu.in/_payment).
   • A JavaScript channel `PayUBridge` is injected onto callback pages
     (surl/furl) to extract transaction ID, mihpayid (PayU Money ID), status,
     and response hash directly from DOM inputs and URL fragments.

3. NATIVE UPI INTENT PACKAGE VISIBILITY:
   • Navigation interceptor detects deep-link schemes (`tez://`, `phonepe://`,
     `paytmmp://`, `upi://`) and routes them through `url_launcher` in
     `LaunchMode.externalApplication`.
   • Android 11+ `<queries>` and iOS `LSApplicationQueriesSchemes` are preconfigured.

4. DEVELOPER SANDBOX QUICK-TEST TOOLBAR:
   • In Sandbox mode (`PAYU_ENVIRONMENT=sandbox`), a floating developer toolbar
     provides 1-click test triggers: "Quick Test Success" and "Cancel" with valid
     mock signatures so developers don't have to repeatedly type test card numbers.

5. IDEMPOTENT BACKEND SYNCHRONIZATION:
   • Cloud Function `verifySubscription` verifies response hashes and avoids duplicate
     writes. Server-to-server webhook `payuWebhook` logs all audits in `payment_logs`.

### 2. PLATFORM CONFIGURATIONS

#### A. Android Configuration (`android/app/src/main/AndroidManifest.xml`)
Add package visibility query permissions inside `<manifest>` for Android 11+ (API Level 30+) UPI support:
```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

    <queries>
        <!-- UPI Intent Scheme for Android 11+ Package Visibility -->
        <intent>
            <action android:name="android.intent.action.VIEW" />
            <data android:scheme="upi" />
        </intent>
        <intent>
            <action android:name="android.intent.action.PAY" />
            <data android:scheme="upi" />
        </intent>

        <!-- Installed UPI Application Packages -->
        <package android:name="com.google.android.apps.nfc.pay" />
        <package android:name="com.google.android.apps.tez" />
        <package android:name="com.phonepe.app" />
        <package android:name="net.one97.paytm" />
        <package android:name="in.org.npci.upiapp" />
```

### 4. CORE SERVICE & DATA MODELS (`lib/services/payu_service.dart`)
Implement `PayUParams`, `PayUResult`, and `PayUService` with:

1. **Input Sanitization**:
   - `sanitizePhone`: Extract exact 10 digits (remove spaces/country code; fallback to '9999999999').
   - `sanitizeName`: Alpha-numeric only; fallback to 'Customer'.
   - `sanitizeProductInfo`: Clean characters; fallback to 'Subscription' or 'Order'.
   - `sanitizeEmail`: Regex validator; fallback to valid format.

2. **SHA-512 Hash Generation**:
   - Request Hash Formula:
     `sha512(key|txnid|amount|productinfo|firstname|email|udf1|udf2|udf3|udf4|udf5||||||salt)`
   - Response Hash Formula:
     `sha512(salt|status||||||udf5|udf4|udf3|udf2|udf1|email|firstname|productinfo|amount|txnid|key)`
   - Amount formatted strictly with 2 decimals: `amount.toStringAsFixed(2)`.

3. **Dual Hash Engine (Backend First + Local Fallback)**:
   - `buildPostDataAsync`: Calls backend Cloud Function (`generatePayUHash`). If backend is unavailable or times out, seamlessly falls back to local `buildPostData`.
   - `verifyResponseHash`: Validates response authenticity against secret salt.

Build the `PayUCheckoutScreen` using `webview_flutter`:

### 6. BACKEND CLOUD FUNCTIONS / API ENDPOINTS (Node.js / Firebase Functions v2)
Implement the following backend functions in `functions/index.js`:

1. `generatePayUHash` (Callable / HTTP):
   - Computes SHA-512 request hash using merchant salt.
   - Returns prepared `postData` map.

2. `verifySubscription` / `verifyPayment` (Callable / HTTP):
   - Verifies response hash signature.
   - Checks idempotency (prevents duplicate processing of same `txnid`).
   - Updates database record with status (`SUCCESS` / `FAILED`), `paymentTxnId`, and `payuMoneyId`.

3. `payuWebhook` (HTTP onRequest):
   - Handles asynchronous server webhooks from PayU.
   - Logs transactions in `payment_logs/{txnid}`.
   - Renders a clean status HTML response for browser redirects to notify the mobile app's JS bridge.

4. `payuResponse` (HTTP onRequest):
   - Standalone handler for `surl` / `furl` redirects.
