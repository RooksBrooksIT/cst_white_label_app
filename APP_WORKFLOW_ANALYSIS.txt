1. EXECUTIVE OVERVIEW & ARCHITECTURAL FOUNDATION
================================================================================

1.1 Purpose & Domain
The CST White Label Application (internally known as E-Bricks) is an enterprise-grade
Construction Resource Planning (ERP) and Site Management Software. It bridges corporate
organizations, field operations managers, site supervisors, subcontractors, workers,
and clients into a single unified real-time ecosystem.

1.2 Key Architectural Components:
- Presentation Layer: Responsive Flutter UI adapting gracefully across mobile, tablet,
  and desktop form factors with custom HSL/Color-blend dynamic gradient design tokens.
- State Management: ValueNotifier/ValueListenableBuilder, Streams (Firestore snapshot listeners),
  StatefulWidgets, and decoupled business logic services.
- Data Layer: Cloud Firestore multi-tenant NoSQL structure organized under corporate
  tenant spaces, site sub-collections, master registers, and global transaction ledgers.
- White-Label Customization Engine: Dynamic company branding (`AppTheme`), adaptive primary
  color palettes, dynamic app icons/logos, company name injection, and splash/portal branding.
- Connectivity & Offline Resilience: `ConnectivityWrapper`, `OfflineSyncService`, and cached
  storage mechanisms ensuring seamless offline site data entry and automated sync on reconnect.
- Cloud Push Notifications: Integrated Firebase Cloud Messaging (FCM) via `NotificationService`
  and dynamic deep-link router `NotificationRouter`.

2. USER ROLES, ACCESS CONTROL & PERMISSION HIERARCHY
================================================================================

The system enforces strict role-based access control (RBAC) across 4 primary user roles
and secondary contractor/worker profiles:

1. ORGANIZATION ADMIN (Super Admin / Corporate Owner)
   - Scope: Complete enterprise-wide governance across all company sites, financial ledgers,
     budgets, master inventories, subscription plans, and white-label branding.
   - Key Capabilities: Add/remove managers and supervisors, approve high-value material and
     financial requests, manage corporate subscriptions via PayU, configure master rate cards.

2. PROJECT / OPERATIONS MANAGER (Field Operations Controller)
   - Scope: Day-to-day oversight of multiple allocated construction sites, project stages,
     approvals, material allocations, machinery tracking, and labour deployment.
   - Key Capabilities: Create and configure new sites/projects, approve supervisor material
     and tool requests, verify daily site logs, manage contractor bills, approve petty cash.

3. SITE SUPERVISOR (Frontline Field Executioner)
   - Scope: Direct on-site management of designated construction sites.
   - Key Capabilities: Submit daily site reports (DSR), request materials and machinery,
     mark labour attendance, record on-site petty cash expenses, log contractor progress.

4. CLIENT / CUSTOMER (Project Stakeholder & Beneficiary)
   - Scope: Read-only transparent window into their specific project(s).
   - Key Capabilities: View live site completion percentage, milestone photos, financial
     payment status, stage timeline progress, and summary reports.

5. CONTRACTORS, LABOURERS & DRIVERS (Subcontractor Entities)
   - Scope: Managed resources tracked for daily attendance, piece-rate wages, task allocation,
     vehicle trip logs, tool transfers, and settlement payouts.

3. AUTHENTICATION, ONBOARDING & SETUP WORKFLOWS
================================================================================

3.1 Cold Start & Splash Sequence:
1. `SplashScreen` loads app configuration, initializes Firebase options, local cache, and
   FCM token handlers.
2. `AppTheme.initialize()` fetches the active organization's dynamic branding (colors, logo, app name).
3. If an authenticated session exists in `AuthService`, the user is routed directly to their
   designated portal (`OrganizationDashboard`, `ConfigAccountDashboard`, `SupervisorDashboard`,
   or `CustomerDashboard`).
4. If unauthenticated, the user is navigated to `/landing` (`LandingPage`).

3.2 Role-Based Login & Onboarding Routes:
- `/landing` (Landing Page): Introduces the platform, features, and direct entrance routes.
- `/authSelection` (`MainDashboard`): Role selector allowing users to choose their portal:
  * Organization Login (`/orgLogin` -> `Organisation_LoginPage`)
  * Manager Login (`/managerLogin` -> `ConfigLoginPage`)
  * Supervisor Login (`/supervisorLogin` -> `SupervisorLoginPage`)
  * Customer Login (`/customerLogin` -> `CustomerLoginPage`)
- `/orgRegistration` (`OrganisationLandingPage` & `OrganisationRegistrationPage`):
  * Organization sign-up workflow capturing company name, email, phone, business address,
    registration certificate, and initial admin credentials.
- `/pricing` (`PricingScreen`) & `/payuCheckout` (`PayuCheckoutScreen`):
  * Subscription selection (Starter, Professional, Enterprise tiers) with automated PayU payment
    gateway checkout and webhook verification.
- `/joinByReferral` (`JoinByReferralPage`):
  * Staff onboarding where managers, supervisors, and staff join an organization using an
    invite code/referral token.
- `/resetPassword` (`ResetPasswordScreen` & `OrgResetPasswordScreen`):
  * Self-service password recovery via Firebase Auth password reset emails.

9. CORE END-TO-END BUSINESS WORKFLOWS & DATA LIFECYCLES
================================================================================

9.1 End-to-End Material Request Lifecycle:
[Supervisor Indent]
   |--> Supervisor identifies material shortage on site.
   |--> Submits Material Request via `MaterialRequestForm` (item, qty, unit, urgency).
[Manager Review]
   |--> Notification pushed to Manager's Approval Desk.
   |--> Manager checks central warehouse inventory via `MaterialInventoryService`.
   |--> If available: Dispatches from warehouse or initiates site-to-site transfer.
   |--> If purchase needed: Approves request and forwards to Organization for procurement.
[Organization Clearance]
   |--> Org Admin authorizes procurement purchase order.
[Dispatch & Delivery]
   |--> Vendor/Yard dispatches material with delivery challan.
[Site Receipt & Stock Update]
   |--> Supervisor verifies shipment at site, uploads challan photo, logs GRN in `MaterialAtSiteEntryPage`.
   |--> Firestore automatically increments active on-site inventory ledger.

9.2 End-to-End Petty Cash Allocation & Expense Lifecycle:
[Fund Allocation]
   |--> Org Admin disburses initial petty cash pool to Manager via `OrgPettyCashPage`.
   |--> Manager allocates micro-wallets to designated Site Supervisors via `ManagerPettyCashPage`.
[Field Expense]
   |--> Supervisor incurs emergency site expense and logs entry in `SupervisorPettyCashPage`.
   |--> Captures receipt photo, vendor name, amount, expense category, and site ID.
[Manager Audit & Approval]
   |--> Manager inspects expense entry, verifies receipt clarity, and approves/rejects voucher.
[Settlement & Top-Up]
   |--> Approved vouchers reconcile the supervisor's wallet balance.
   |--> Low balance triggers automated top-up request to the Manager/Organization vault.

9.3 End-to-End Project Creation to Handover Lifecycle:
1. Setup: Org or Manager creates project via `ProjectSetupWizard` (GPS, budget, stages, supervisors).
2. Preparation: Drawings/Blueprints uploaded to `ConfigLayoutAndDrawing`; tools and initial stock mapped.
3. Execution: Daily site reports (DSR), worker attendance, material intake, and petty cash logs recorded daily.
4. Monitoring: Managers and Org Admins track milestones, approve stage completions, and monitor financial burn.
5. Reporting: Ongoing PDF reports generated for internal review and customer updates.
6. Handover: Final inspection completed, defect liability list resolved, and site marked "Completed".

10. CROSS-CUTTING PLATFORM SERVICES
================================================================================

10.1 Cloud Notifications (`NotificationService`, `NotificationRouter`, `NotificationModel`):
- Handles FCM device registration, foreground heads-up banners, background wakeups, and notification center.
- Deep links users straight to the relevant approval request, site status page, or chat thread on tap.

10.2 Offline Synchronization (`OfflineSyncService`):
- Intercepts network calls when device is offline in remote construction locations.
- Queues Firestore mutations locally in encrypted local storage.
- Automatically flushes and syncs queued data upon network restoration without data loss.

10.3 Dynamic White-Label Engine (`AppTheme`):
- Live `ValueListenable` system that updates primary, dark accent, and gradient background colors instantly
  when branding settings change in Firestore.
- Computes harmonious color schemes (HSL mathematical tone adaptation) to maintain consistent visual appeal.

10.4 Payment Gateway Engine (`PayuService`, `PayuCheckoutScreen`):
- Secure server-verified hash generation for PayU checkout.
- Handles success/failure callbacks, subscription limit activations, and billing transaction histories.
